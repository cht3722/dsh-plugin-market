安装前先确认
Insight 是外部运行环境；Bundle 只负责 DSH 侧插件和检查入口。语义评审还会使用 Provider Auth 和模型 token。

      
DSH 与 Node
DSH 0.2.1-rc.2；Node.js >=24
Insight 服务
Insight CLI 在 PATH 中，服务可访问
模型评审
仅 /score --semantic 需要 Provider Auth 和 token 预算

      
Insight 是外部运行环境＋
Bundle 安装 DSH 侧组件，但不会自动安装 Insight CLI 或启动外部服务。
语义评审会产生模型调用＋
普通读卡和重算不调用 LLM；只有显式使用 /score --semantic 才会请求 Provider 并消耗 token。
评分依赖导入覆盖度与服务版本＋
会话未完整导入、服务版本不匹配或评分配置变化时，结果可能不同；请结合覆盖度与置信信息判断。

    


    

      
五步，完成第一次导入与读分。
先准备 Insight 运行环境，再从市场安装 Bundle，最后用当前会话做一次最小验证。

      
本页步骤
  1. 准备运行环境
  2. 从市场安装 Bundle
  3. 确认依赖就绪
  4. 导入当前会话
  5. 读回评分卡
完整安装文档 ↗

        
  1. 01
    准备运行环境
    确认 Node.js 24+、DSH 0.2.1-rc.2，并确保 Insight CLI 与服务可用。
    运行条件
    node --version
# DSH 0.2.1-rc.2
# Insight CLI 与服务均可用
    完成后应看到返回 Node.js 24+；插件配置页显示 Insight CLI 可用、服务运行中。
    没有 CLI 时先在插件配置页查看安装指引；CLI 已安装但服务未启动时，可直接点击启动实例。
  2. 02
    从市场安装 Bundle
    在 DSH 的插件市场添加索引，安装 Insight 1.0.0。
    插件市场索引
    https://fuxi-ailabs.github.io/dsh-plugin-market/index.json
    完成后应看到Bundle 出现在已安装插件列表，重启后 Provider Auth、Insight 和环境检查组件均运行中。
    安装后重启 DSH，确保 Host 和 Client 模块重新加载。
  3. 03
    确认依赖就绪
    打开插件管理页中的 Insight Bundle，在配置区检查 Provider Auth 与 Insight 状态。
    检查位置
    插件 → Insight → 配置 → 环境检查
    完成后应看到Provider Auth 正常，Insight CLI 与服务正常，异常数为 0。
    预期看到 Provider Auth 正常，以及 Insight CLI 可用、服务运行中。
  4. 04
    导入当前会话
    在 DSH 中执行 /insight，导出并导入当前会话，然后打开 Insight 会话页。
    发送给 DSH
    /insight
    完成后应看到会话成功导入，Insight 会话页可打开。
    如果只想检查服务状态，可先执行 /insight --status。
  5. 05
    读回评分卡
    执行 /score，核对总分、覆盖度和各维度分数；需要语义评审时再显式使用 --semantic。
    发送给 DSH
    /score
    完成后应看到回执显示总分、覆盖度和各维度评分。
    确定性读卡不调用 LLM；只有 --semantic 会消耗模型 token。
